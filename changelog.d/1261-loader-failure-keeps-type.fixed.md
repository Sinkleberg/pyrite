- A file whose type's loader raises (a value that will not convert, a missing field, a plugin validator) is reported as malformed by `pyrite index sync` and `pyrite index health`, naming the file and the loader's message. It used to be indexed silently as an `event`, so a `backlog_item` with a bad `rank` disappeared from `pyrite sw backlog`. `pyrite get`, MCP `kb_get` and REST `GET /api/entries/{id}` still return such a file, as the type it declares, with a `load_problems` list (`field`, `rule`, `severity`, `message`, the shape of an update warning); a refused field is absent from the reply, never shown as the type's default. `update` that fixes the field repairs the file, and an update of another field succeeds with a warning and never moves the file. A file whose frontmatter is empty (`---` then `---`) loads as a note, like any file with no `type:`. (#1261)
